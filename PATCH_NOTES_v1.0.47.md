# GRPGI 1.0.47 — Web deploy false-403 rollback fix

## Исправлено

- HTTP 403 больше не запускает rollback уже корректно загруженной web-версии.
- Серверная проверка деплоя теперь проверяет фактические файлы после атомарного переключения каталога:
  - `index.html`
  - `app/index.html`
  - `app/app.js`
  - `app/runtime-config.js`
- Если загрузка или переключение каталога повреждены, предыдущая версия по-прежнему восстанавливается.
- Публичные URL проверяются после успешной публикации как диагностика. HTTP 403/5xx/timeout отображаются как предупреждение, но не уничтожают новый деплой.
- Обновлён текст DEV-панели, чтобы он соответствовал новой стратегии.

## Причина

Локальный `curl --resolve ... 127.0.0.1` попадал под правила Caddy/WAF, отличающиеся от обычного браузерного запроса, и получал `403`. При этом публичный сайт отвечал успешно. Из-за этого предыдущая схема делала ложный rollback.

## Проверки

- `node --check` для изменённых JS/CJS.
- JSON parse для package/build-info.
- npm не запускался.
