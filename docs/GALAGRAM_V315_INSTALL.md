# GalaGram v315 и игровые встречи v316: установка и использование

Нужны Node.js 22+ на сервере и существующий PocketBase с модулями авторизации v212 и синхронизации мира v301. Рейды остаются отключёнными. Служба уведомлений обслуживает расписание публикаций и Web Push; сроки резервов игровых встреч проверяет PocketBase. Нового процесса или порта для встреч нет.

## После слияния PR — PowerShell на компьютере

Выполняйте блоки сверху вниз из каталога проекта. Замените YOUR_SERVER адресом своего сервера. В текущей установке PocketBase слушает **8090**, биржа использует отдельный адрес/порт.

```powershell
git pull
$RaidServer = "root@YOUR_SERVER"

ssh $RaidServer "mkdir -p /opt/pocketbase/hook-backups-v315 /opt/grpgi-notifications && cp -a /opt/pocketbase/pb_hooks/. /opt/pocketbase/hook-backups-v315/"
ssh $RaidServer "systemctl stop pocketbase"

scp pocketbase/pb_hooks/galagram-v315.js pocketbase/pb_hooks/grpgi_galagram_v315.js pocketbase/pb_hooks/grpgi_galagram_v315.pb.js "${RaidServer}:/opt/pocketbase/pb_hooks/"
scp pocketbase/pb_hooks/grpgi_planning_v316.js pocketbase/pb_hooks/grpgi_planning_v316.pb.js "${RaidServer}:/opt/pocketbase/pb_hooks/"
scp notification-service/package.json notification-service/package-lock.json notification-service/worker.cjs notification-service/configure.cjs "${RaidServer}:/opt/grpgi-notifications/"
scp notification-service/grpgi-notifications.service "${RaidServer}:/etc/systemd/system/"

ssh $RaidServer "cd /opt/grpgi-notifications && npm ci --omit=dev --ignore-scripts && node configure.cjs && chown -R pocketbase:pocketbase /opt/grpgi-notifications"
```

Последняя команда создаёт `/etc/grpgi-notifications.env` с правами `600`. Закрытый VAPID-ключ и токен генерируются на сервере и не печатаются. Повторный запуск сохраняет существующие ключи. Не удаляйте этот файл при обновлениях: смена VAPID-ключей потребует повторного включения подписок в браузерах.

```powershell
ssh $RaidServer "mkdir -p /etc/systemd/system/pocketbase.service.d"
ssh $RaidServer "printf '[Service]\nEnvironmentFile=/etc/grpgi-notifications.env\n' > /etc/systemd/system/pocketbase.service.d/galagram-v315.conf"
ssh $RaidServer "systemctl daemon-reload && systemctl restart pocketbase && systemctl enable grpgi-notifications && systemctl restart grpgi-notifications"
ssh $RaidServer "systemctl status pocketbase grpgi-notifications --no-pager"
ssh $RaidServer "journalctl -u grpgi-notifications -n 30 --no-pager"
```

Если загрузка файлов или npm завершается ошибкой, запустите PocketBase обратно: `ssh $RaidServer "systemctl start pocketbase"`, устраните ошибку и повторите установку. Дополнительный TCP-порт не открывается: процесс обращается к PocketBase по loopback. `grpgi-raids` запускать не нужно.

После установки серверных файлов перезапустите Electron-приложение и выполните **Deploy Web**. На сайте обновите страницу. Изменения схемы индексов/служебных таблиц и разрешение аудиофайлов выполняются новым hook при старте; ручного импорта коллекций нет.

Для аудио установлен лимит **32 МиБ**. Если обратный прокси возвращает HTTP 413, проверьте его предел тела запроса; для такого лимита потребуется как минимум `client_max_body_size 40m` в обслуживающем сайт блоке nginx, затем проверка конфигурации и reload nginx.

## Проверка

1. В профиле сайта откройте «Уведомления GalaGram», нажмите «Включить на этом устройстве» и подтвердите системный запрос браузера.
2. Выберите нужные категории (сообщения, новости, новые задания, игровые встречи) и нажмите «Проверить уведомление». Тест проходит через серверную очередь, а не через локальную имитацию.
3. С другого персонажа отправьте сообщение. Проверьте уведомление при скрытой/закрытой вкладке и переход в нужную переписку.
4. В World Config создайте новость, выберите «Отложить» и реальное время на несколько минут вперёд. До выпуска сервером она отсутствует в ленте; после — появляется и отмечается как непрочитанная.
5. Откройте HTML-поле новости через ПКМ → «Аудиофайл с компьютера». Поддержаны MP3, M4A, OGG, WAV, WebM; воспроизведение, пауза, перемотка и громкость доступны в общем плеере приложения и сайта.
6. «Размер изображения» работает с тегом `<img>` под курсором или выделенным целиком. Ширина задаётся в пикселях, высота сохраняет пропорции, размер ограничен шириной текста. При вставке нового изображения также появляется выбор размера.

7. Сохраните задание в World Config, затем нажмите в его редакторе «Настроить встречи». Предложите даты и лимит. В разделе «Задания» игрок отмечает все подходящие даты; после утверждения ДМом отдельно нажимает «Записаться на игру».
8. Создайте продолжение из предыдущей встречи или укажите прежний состав вручную. После выбора даты задайте срок подтверждения. До срока записывается только приглашённый состав; неподтверждённые места затем освобождаются. Проверьте перенос даты: текущие подтверждения должны стать резервами и потребовать повторного подтверждения.

## Обновление уже установленного PR #173

Если служба уведомлений и ключи уже настроены, после `git pull` достаточно загрузить все пять hook и перезапустить службы:

```powershell
$RaidServer = "root@YOUR_SERVER"
ssh $RaidServer "mkdir -p /opt/pocketbase/hook-backups-v316 && cp -a /opt/pocketbase/pb_hooks/. /opt/pocketbase/hook-backups-v316/"
ssh $RaidServer "systemctl stop pocketbase"
scp pocketbase/pb_hooks/galagram-v315.js pocketbase/pb_hooks/grpgi_galagram_v315.js pocketbase/pb_hooks/grpgi_galagram_v315.pb.js pocketbase/pb_hooks/grpgi_planning_v316.js pocketbase/pb_hooks/grpgi_planning_v316.pb.js "${RaidServer}:/opt/pocketbase/pb_hooks/"
ssh $RaidServer "systemctl start pocketbase && systemctl restart grpgi-notifications"
ssh $RaidServer "systemctl status pocketbase grpgi-notifications --no-pager"
```

При ошибке SCP запустите PocketBase обратно и исправьте загрузку. Перезапустите приложение, выполните Deploy Web и обновите сайт. `/etc/grpgi-notifications.env` сохраняется. Скрипты сборки рейдов не нужны.

## Поведение и ограничения

- Разрешение браузера запрашивается только по нажатию кнопки. Настройки и отключение относятся к этому браузеру/устройству. При выходе и смене персонажа подписка браузера отключается. Текст сообщений не передаётся в push: показывается нейтральная подпись.
- Работает через HTTPS. На iPhone/iPad требуется iOS/iPadOS 16.4 или новее и запуск сайта с домашнего экрана; возможность уведомлений определяет браузер. Доставка зависит от браузера, сети, системных ограничений и push-службы производителя.
- Поддержаны push-endpoint Google FCM, Mozilla, Apple и Windows. Произвольные URL подписки сервер не принимает.
- Служба проверяет очередь раз в 15 секунд; открытые клиенты получают небольшое состояние выпуска примерно раз в 30 секунд. Указанное время публикации — начало обработки, а не гарантия показа с точностью до секунды. При выключенной службе публикация ждёт её запуска.
- Старые опубликованные записи при первой установке индексируются без массовой рассылки. Редактирование новости или задания не повторяет уведомление. Новое доступное задание отправляется отдельной категорией; завершённые и скрытые задания не рассылаются. Черновики, удалённые и недоступные новости не рассылаются. Выпуск уже опубликованной записи повторно не создаёт новую рассылку — для неё нужна новая новость с новым ID.
- Отложенные записи скрываются в ленте до выпуска сервером, но их авторские исходники остаются в общем снапшоте World Config. Это не отдельное защищённое хранилище будущих сюжетных материалов.
- Расписание и публикации хранятся в служебных SQL-таблицах `grpgi_social_*_v315`, исходные новости редактируются через существующий World Config. Сохранение не ждёт push. Повтор отправки заменяет системное уведомление той же группы; service worker хранит квитанции последних 512 событий, включая перезапуск браузерного обработчика.
- Повторные неудачи ограничены восемью попытками; ответы 404/410 удаляют истёкшую подписку. Для диагностики используйте журнал службы. Доставку реальным устройствам нужно проверить после установки: локальные тесты не заменяют проверку настроек браузеров и сети сервера.
- Игровая дата новой новости автоматически использует 3616 год. Реальные `createdAt`, время расписания и даты очереди сохраняются для работы сервера. Старые даты 2026 нормализуются при показе/сортировке; явно заданные исторические даты мира не переписываются в хранилище.

- Встречи, голоса, резервы и квитанции операций хранятся отдельно в `grpgi_planning_*_v316`. Полный снапшот кампании при голосовании/записи не записывается. Открытый экран проверяет небольшой курсор раз в 15 секунд; сроки резервов дополнительно проверяются cron PocketBase раз в минуту и при каждом действии. Даже при задержке cron просроченный резерв не блокирует запись после серверной проверки.
- Вместимость проверяется транзакцией SQLite. Одно место учитывается на профиль персонажа; ограничения на человека с несколькими профилями пока нет. Очередь ожидания не реализована. Дату утверждает ДМ; срок подтверждения он вводит явно.
- Категория «Игровые встречи» включает открытие голосования, выбор/перенос даты, открытие общей записи и отмену. Уведомления не создают запись автоматически. Встречи используют реальные даты, UTC в хранилище и локальное время в интерфейсе.

Остановка уведомлений и расписания: `systemctl disable --now grpgi-notifications`. Она не удаляет новости, очередь или существующие данные кампании; сроки встреч продолжает проверять PocketBase. Для отключения встреч отдельно уберите их два hook при остановленном PocketBase, затем перезапустите его. Для удаления новых hook нужно остановить PocketBase, убрать три файла v315 и два файла v316 и drop-in `galagram-v315.conf`, выполнить `systemctl daemon-reload` и запустить PocketBase. Для полного отката клиента также верните соответствующую версию приложения/сайта: новые клиенты намеренно ждут серверного выпуска отложенных записей.

Документация платформы: [Web Push на iOS/iPadOS](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/), [web-push для Node.js](https://github.com/web-push-libs/web-push).
