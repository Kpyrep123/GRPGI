# Выбор задания, даты и запись на игру — v316

Реализовано в PR #173 для сайта и Electron. Раздел «Задания» использует согласованный интерфейс: карточки заданий → все подходящие даты → отдельная запись. [Автономный макет](prototypes/game-planning.html) остаётся примером оформления, рабочая версия использует серверные данные.

## Использование

1. ДМ сохраняет задание в World Config и нажимает «Настроить встречи» в его редакторе. Также создать встречу можно в разделе «Задания».
2. Встреча содержит от 1 до 12 разных будущих дат и лимит от 1 до 100 участников (в форме по умолчанию 6). Необязательный срок голосования задаётся до первой предложенной игры.
3. Игрок может отдельно выразить интерес и отметить все подходящие даты. Пустой сохранённый ответ означает, что ни одна дата не подходит. Голоса не занимают места.
4. ДМ видит число доступных участников для каждого варианта и утверждает дату. Автоматического выбора победителя нет.
5. Для новой игры открывается общая запись. Игрок явно подтверждает участие. Отказ освобождает место.
6. Старые описания и прогресс заданий остаются в раскрываемом блоке под новым интерфейсом. Смена статуса задания и завершение игровой встречи — отдельные действия.

## Продолжение и перенос

Продолжение создаёт новую встречу той же серии. Из предыдущей встречи берётся подтверждённый состав; ДМ может изменить приглашения перед утверждением даты. Для первой установки можно отметить «Продолжение партии» и вручную выбрать прежних участников без старой записи встречи.

Даты продолжения выбирает приглашённый состав. После утверждения даты ДМ задаёт обязательный срок подтверждения: в будущем и не позже начала игры. Приглашённым резервируются места; они входят в лимит. Подтверждение переводит свой резерв в запись, не добавляя второе место. До срока приглашённые подтверждают или отказываются; остальные видят условия. По окончании срока неподтверждённые резервы освобождаются и открывается общая запись.

Лимит нельзя уменьшить ниже занятых/зарезервированных мест или приглашённого состава до выбора даты. При переносе текущие участники становятся приглашёнными с резервами до нового срока. Прошлая запись не подтверждает другую дату автоматически. Старые команды отклоняются по версии расписания. История дат сохраняется. С началом игры запись закрывается; завершение отмечает ДМ.

## Уведомления

В настройках Web Push есть отдельная категория «Игровые встречи». Разрешение браузера запрашивается только явным нажатием кнопки включения уведомлений.

| Событие | Получатели |
|---|---|
| Открыто голосование | Доступные заданию игроки; в продолжении — приглашённый состав |
| Утверждена дата | Заинтересованные/ответившие и приглашённые |
| Дата перенесена | Участники, приглашённые, заинтересованные/ответившие |
| Открылась общая запись | Приглашённые, участники и заинтересованные/ответившие |
| Игра отменена | Участники, приглашённые и заинтересованные/ответившие |

Отправитель не получает собственное уведомление. Перед отправкой сервер повторно проверяет права, актуальную версию и состояние встречи. Повтор операции не создаёт повторную рассылку. Нажатие открывает нужную встречу. Новое задание остаётся отдельной категорией; правки описания не рассылаются как новое задание.

## Даты и интерфейс

Расписание использует реальные даты встреч людей. Год 3616 остаётся датой событий мира и новостей. ДМ вводит даты в часовом поясе своего устройства; момент сохраняется в UTC вместе с названием пояса. Игрок видит своё локальное время, при отличии — также время ДМа. Оба подписаны обозначением пояса.

Общий компонент `checkbox-picker-v172` используется для дат и приглашённых. Несохранённые ответы, выбор ДМа и открытые формы не сбрасываются при проверке обновлений. Изменение версии самих вариантов сбрасывает старую доступность, сохраняя интерес к заданию. Отмена формы ничего не сохраняет. После потери сетевого ответа повтор использует прежний ID операции.

## Сервер и синхронизация

- Hook: `grpgi_planning_v316.js` + `grpgi_planning_v316.pb.js`.
- Авторизованные API: GET `/api/grpgi/auth-v212/planning-v316/state`, POST `/api/grpgi/auth-v212/planning-v316/mutate`.
- Закрытые SQL-таблицы `grpgi_planning_sessions_v316`, `grpgi_planning_votes_v316`, `grpgi_planning_regs_v316`, `grpgi_planning_ops_v316`, `grpgi_planning_clock_v316`. Публичных CRUD-коллекций нет. Таблицы создаются при старте PocketBase.
- Голоса и записи не меняют снапшот World Config. Метаданные заданий читаются из актуального индекса v301; при его отсутствии/отставании — из снапшота. Клиент получает только сведения о заданиях и встречах.
- Открытый экран или окно проверяет курсор раз в 15 секунд и при возврате на вкладку. Неизменившиеся данные не отправляются повторно. Push использует существующую службу v315; нового процесса/порта нет.
- Каждая команда проверяет права на кампанию и задание, срок, версию и вместимость внутри транзакции. SQLite writer резервируется до чтения остатка мест. Операция и её квитанция сохраняются в той же транзакции; потеря ответа допускает безопасный повтор.
- Расписание и настройки ДМа имеют отдельные версии. Изменившуюся параллельно форму сервер отклоняет, сохраняя клиентский черновик для проверки.
- Сроки резервов проверяются PocketBase cron раз в минуту, а также при чтении состояния/действиях. После простоя сервера истёкшие резервы освобождаются при следующей проверке.

## Проверки и ограничения

`tests/planning-v316.server.cjs` выполняет настоящие SQL-запросы production-hook и очередь v315: многовариантное голосование, права и видимость, повтор/подмена ID операции, версии, продолжение, истечение резервов, перенос, отмена, перезагрузка базы. Два SQLite-соединения соревнуются за последнее место при незавершённой транзакции; после повтора второй запрос получает «мест нет».

`tests/planning-v316.dom.mjs` выполняет общий клиент в DOM: выбор дат, сохранение черновиков при обновлении, повтор после потери ответа, решение ДМа, запись, перенос и подтверждение, отмена окна, закрытие оверлея, выход. Общий прогон — `node tools/test-pr.cjs`.

Одно место учитывается на профиль персонажа. Общего аккаунта человека для нескольких персонажей и очереди ожидания пока нет. Доставка Web Push на реальное устройство проверяется после установки; локальные проверки не подтверждают доступность push-служб с сервера.
