# Выбор задания, даты и запись на игру

Статус: проект для обсуждения. Голосование и запись пока не подключены к приложению/серверу. В PR #173 дополнительно реализованы только уведомления о новых заданиях.

Интерактивный автономный макет: [prototypes/game-planning.html](prototypes/game-planning.html). Он использует встроенную копию общего checkbox-picker-v172 и демонстрационные данные; запросов к серверу и настоящей записи нет.

## Согласовано

- ДМ заранее предлагает даты и максимальное число игроков.
- Игрок отмечает **все подходящие даты**, а не только одну.
- Голосование не занимает место: после утверждения даты нужна отдельная запись.
- В продолжении партии прежний состав получает первое окно подтверждения.
- После заполнения лимита новые записи запрещены сервером.
- Для продолжений нужны отдельные уведомления о выбранной/изменённой дате.

## Три экрана в разделе «Задания»

| Экран | Содержимое | Главное действие |
|---|---|---|
| Задания | Карточки миссий, короткое описание, новая игра/продолжение, состояние планирования | Выразить интерес / перейти к датам |
| Подходящие даты | Все предложенные варианты, доступность игроков, мой сохранённый ответ | Отметить все подходящие даты и сохранить |
| Запись на игру | Утверждённая дата, состав, подтверждённые/зарезервированные/свободные места, сроки | Подтвердить участие / записаться / освободить место |

Утверждённая ближайшая встреча закрепляется над списком заданий. У игрока основной статус всегда явный: «Вы ещё не ответили», «Доступность сохранена», «Подтвердите участие», «Вы записаны», «Мест нет».

Оформление: существующая тёмная янтарная тема; обычные карточки без перегруженной таблицы; на телефоне колонки становятся одной. Несколько подходящих дат выбираются общим компонентом с чекбоксами. Счётчики мест показывают отдельно подтверждения, резервы и свободные места.

## Предлагаемые правила, ещё не утверждённые

1. Интерес к заданию и доступность по датам показываются раздельно. Голос за задание можно изменить до закрытия выбора. Количество голосов не ограничивается числом мест.
2. ДМ утверждает **пару «задание + дата»**. Интерфейс рекомендует наиболее доступный вариант, но не назначает победителя автоматически: при равенстве голосов и сюжетных ограничениях решение остаётся за ДМом.
3. Предложенные даты можно отмечать независимо для разных заданий. Это не обязывает записываться сразу на несколько игр.
4. Новая игра после утверждения даты открывается для записи по порядку успешно принятых сервером заявок.
5. Окно подтверждения продолжения задаёт ДМ; после его окончания запись открывается для остальных. До окончания окна новые игроки только видят условия, но записаться не могут.
6. Список приглашённых на продолжение ДМ видит и при необходимости меняет перед открытием окна. Игрок, отказавшийся от участия, сразу освобождает свой резерв.
7. Резервный список в первой версии не нужен. Если он потребуется, он должен быть отдельным состоянием, которое не занимает основное место.

## Продолжение партии

У задания может быть несколько игровых встреч с собственной датой, составом и номером. Продолжение — новая встреча той же серии, а не перезапись старой.

1. ДМ создаёт продолжение из предыдущей встречи. Предыдущий состав становится приглашённым составом новой встречи.
2. Предлагаются даты; доступность сначала собирается с приглашённых участников.
3. После утверждения даты они получают «Выбрана дата продолжения. Подтвердите участие до …».
4. Каждому приглашённому зарезервировано место. Подтверждение переводит его собственный резерв в подтверждённое участие, а не добавляет ещё одно место.
5. По сроку неподтверждённые резервы освобождаются. Подтверждённые записи сохраняются; оставшиеся места доступны другим игрокам.

Лимит нельзя уменьшить ниже суммы подтверждённых мест и действующих резервов. Если прежний состав больше нового лимита, ДМ сначала определяет приглашённый состав; система не выбирает исключённых игроков случайно или по скорости нажатия.

## Перенос уже утверждённой даты

Перенос создаёт новую версию расписания. Прошлое подтверждение не переносится автоматически на другой день.

- Участники и приглашённые получают «Дата игры изменена: …».
- Их места сохраняются в виде резервов до нового срока подтверждения.
- Каждый подтверждает или отклоняет новую дату.
- Старые кнопки и уведомления с прежней версией даты не подтверждают участие в новой версии молча.
- История дат сохраняется; повторная отправка одной операции не рассылает второе уведомление.

## Уведомления

| Событие | Получатели | Переход |
|---|---|---|
| Новое задание | Доступные ему игроки, включившие категорию «Задания» | Карточка задания; уже реализовано в PR #173 |
| Началось голосование | Участники выбранной кампании; для продолжения — приглашённый состав | Варианты дат |
| Выбрана дата | Голосовавшие/заинтересованные игроки; для продолжения — прежний состав, даже без новой записи | Дата и кнопка участия |
| Изменена дата | Подтвердившие участие и приглашённые | Новая дата и повторное подтверждение |
| Открылась общая запись | Заинтересованные игроки с подходящей доступностью | Свободные места |
| Игру отменили | Записавшиеся и приглашённые | Состояние отменённой встречи |

Уведомления о встречах предлагается сделать отдельной категорией «Игровые встречи». Не смешивать назначение новой даты с публикацией нового задания. Изменение описания задания не является новым заданием и не создаёт рассылку.

## Реальные даты и игровые даты

Расписание встреч использует реальные даты и время. Например, 27 ноября **2026**, 19:00 МСК — время, когда встречаются люди. Год 3616 остаётся датой событий мира и новостей.

Сервер хранит момент в UTC и часовой пояс, выбранный ДМом. Игрок видит свою локальную дату/время и обозначение часового пояса; при отличии можно показать время ДМа рядом. Косметический форматировщик с годом 3616 для расписания встреч не используется.

## Серверная модель следующего этапа

Отдельные записи с небольшими realtime-обновлениями; голоса и места не сохраняются полным снапшотом World Config.

- `game_sessions`: кампания, задание, серия, номер встречи, ДМ, состояние, лимит, варианты/утверждённая дата, сроки, версия расписания.
- `game_session_availability`: встреча, профиль игрока, подходящие варианты, версия набора вариантов; одна запись на профиль и встречу.
- `game_session_registrations`: встреча, профиль, выбранный персонаж, состояние «резерв/подтверждено/отказ», срок резерва, версия подтверждённого расписания; уникальность по встрече и игроку.
- Журнал операций и существующая очередь уведомлений обеспечивают повторяемые запросы без повторного занятия места или рассылки.

Текущая авторизация GRPGI привязана к профилю персонажа. Если одному человеку разрешено иметь несколько профилей, для ограничения «одно место на человека» потребуется общий идентификатор игрока. Без такой привязки сервер может гарантировать только одно место на профиль; это нужно определить перед внедрением регистрации.

В одной транзакции сервер проверяет права, актуальную версию расписания, срок резервов, отсутствие повторной записи и остаток вместимости. Два параллельных запроса на последнее место не могут оба завершиться успешно. Закрытая кнопка в браузере — только подсказка; лимит обеспечивает сервер.

## Что согласовать перед реализацией

- Окончательное утверждение задания и даты остаётся за ДМом или нужен автоматический выбор по заранее заданному правилу?
- Длительность окна подтверждения: задаётся ДМом для каждой встречи; значение по умолчанию ещё не выбрано.
- Учёт места по профилю персонажа или добавление общего аккаунта игрока для нескольких персонажей.
