# Supabase sync setup

## Что делает эта сборка

- хранит локальные файлы мира и локальный state как раньше
- при входе и на старте проверяет, нет ли в Supabase более новой ревизии
- при сохранении сначала пишет локально, потом проверяет облако и пушит только если ревизия не изменилась
- при конфликте не затирает облако автоматически
- изображения сохраняются локально в `world-data/assets`, а при включённом Supabase дополнительно грузятся в Storage bucket `campaign-assets`
- перед push приложение нормализует локальные `file://` картинки в публичные Storage URL, чтобы другие ПК могли их загрузить

## Как подготовить Supabase

1. Создай проект Supabase.
2. Открой SQL Editor.
3. Выполни содержимое файла `supabase-setup.sql`.
4. Убедись, что bucket `campaign-assets` существует и является public.
5. Возьми `Project URL` и `Publishable key` (или legacy `anon key`).
6. В приложении открой `SYNC_PANEL`.
7. Заполни:
   - `SUPABASE_URL`
   - `PUBLISHABLE / ANON KEY`
   - `CAMPAIGN_ID` — одинаковый у всех ПК этой кампании
   - `DEVICE_LABEL` — уникальное имя устройства, например `dm-main-pc`, `player-v-laptop`
   - `STORAGE_BUCKET` — `campaign-assets` (или свой bucket, если ты поменял SQL)
8. Нажми `SAVE_SYNC_CONFIG`, потом `TEST_CONNECTION`.

## Как обновить уже существующие картинки

Если у тебя в облаке уже лежат старые сущности со ссылками вида `file:///...`, сделай один раз так:

1. Открой новую сборку на том ПК, где находятся оригинальные локальные картинки.
2. Зайди под ДМом.
3. Открой `SYNC_PANEL`.
4. Нажми `PUSH_LOCAL`.

Эта операция перезальёт локальные изображения в Supabase Storage и заменит старые локальные ссылки в облачном снапшоте на публичные Storage URL.

## Как это работает

Приложение хранит в облаке один снапшот кампании на `campaign_id`:

- `world_json` — весь мир: игроки, планеты, NPC, предметы, флора, фауна, системы
- `state_json` — живое состояние игроков: кредиты, инвентарь, профильные изменения
- `revision` — номер ревизии для optimistic concurrency
- картинки сущностей — в Supabase Storage, а в JSON хранится уже публичный URL

Если другой ПК уже записал новую ревизию, приложение покажет конфликт и не перезапишет данные слепо.

## Важно про безопасность

Текущий SQL рассчитан на доверенную закрытую группу игроков. Политики `anon` здесь намеренно permissive, чтобы сборка заработала без отдельной auth-системы.

Если нужна более жёсткая безопасность, следующий шаг — перейти на Supabase Auth или на свой серверный прокси / Edge Function, чтобы не давать прямую запись из desktop-клиента всем, кто знает ключ проекта.
