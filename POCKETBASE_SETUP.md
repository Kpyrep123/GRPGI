# Настройка PocketBase

Приложение использует PocketBase как основной удалённый backend.

Рекомендуемый публичный адрес:

```text
https://sync.grpg-sync.ru
```

## Коллекции по умолчанию

- `app_users` — auth-коллекция пользователей приложения;
- `campaign_snapshots` — снапшоты мира и общего состояния;
- `campaign_players` — изолированное состояние игроков;
- `campaign_messages` — сообщения чата;
- `campaign_combat_runtime` — активная боевая сцена и runtime;
- `campaign_assets` — изображения и другие ассеты кампании.

Во всех рабочих коллекциях должны присутствовать поля, которые использует приложение в `main.js`. Для доступа к данным задайте правила List/View/Create/Update, разрешающие работу авторизованным записям `app_users`.

Пример базового условия:

```text
@request.auth.id != ""
```

Удаление записей рекомендуется оставить закрытым для обычных пользователей.

## Настройка приложения

В панели синхронизации выберите `PocketBase` и укажите:

```text
POCKETBASE_URL: https://sync.grpg-sync.ru
CAMPAIGN_ID: main
APP_USER_EMAIL: учётная запись из app_users
APP_USER_PASSWORD: пароль этой записи
```

Учётная запись должна быть обычной записью auth-коллекции `app_users`, а не суперпользователем PocketBase.

## Realtime

Приложение подключается к `/api/realtime` и подписывается на коллекции снапшотов, игроков, сообщений и боевого runtime. События дополнительно фильтруются по `campaignId`. Периодический polling остаётся резервным механизмом восстановления после разрыва соединения.

## Транзакционный рынок и пакетные операции 1.0.139

Покупка, продажа и резервирование уникальных товаров выполняются серверным хуком и его модулем реализации:

```text
pocketbase/pb_hooks/grpgi_market.pb.js
pocketbase/pb_hooks/grpgi_market.js
```

Скопируйте оба файла в каталог `pb_hooks` рядом с исполняемым файлом рабочего PocketBase и перезапустите PocketBase. Файл `.pb.js` регистрирует маршрут, а обычный `.js` загружается внутри обработчика через `require()`. Такое разделение обязательно: PocketBase выполняет обработчики в изолированном JavaScript-контексте и не сохраняет функции из верхнего уровня `.pb.js`.

Версия 1.0.139 добавляет рядом ещё два файла. Они не заменяют прежние рыночные hooks:

```text
pocketbase/pb_hooks/grpgi_market_v139.pb.js
pocketbase/pb_hooks/grpgi_market_v139.js
```

При переходе с уже установленной 1.0.138 достаточно добавить эти два файла. При чистом переходе с 1.0.136 сначала установите также пять hooks добычи и денег из раздела «Передача добычи и выдача денег 1.0.137–1.0.138» ниже: новый рыночный модуль использует общий `grpgi_loot_core_v137.js`. Никогда не заменяйте рабочий каталог `pb_hooks` целиком — добавляйте только перечисленные файлы.

После перезапуска маршрут `POST /api/grpgi/market/transaction-v139` принимает поле `quantity` от 1 до 10 000. Вся пачка покупается или продаётся одной транзакцией: цена вычисляется сервером, баланс и портфель/инвентарь меняются вместе, а повтор того же `operationId` возвращает прежний результат без второго списания. Для обычных предметов сервер до записи проверяет общий вес и свободное размещение всех экземпляров; уникальный предмет допускает только количество 1. Продажа снаряжения по-прежнему выполняется по одному экземпляру, а пакетная продажа доступна для акций.

Хук автоматически создаёт служебную таблицу `grpgi_market_operations_v139`. В ней хранится результат операции для безопасного повтора после потерянного ответа или перезапуска PocketBase.

После перезапуска неавторизованный `POST /api/grpgi/market/transaction-v139` должен возвращать `401`, а авторизованный запрос с корректным телом — выполнять пакетную транзакцию рынка. Старый маршрут `POST /api/grpgi/market/transaction` можно оставить для совместимости с клиентами до 1.0.139.

Хук использует существующие коллекции `campaign_snapshots` и `campaign_players`; создавать дополнительную коллекцию не требуется. Он выполняет списание или начисление кредитов, изменение инвентаря, портфеля акций и резерв уникального предмета внутри одной транзакции базы данных. Обычные предметы продаются за 70% текущей цены планеты, предметы типа `stock` — за 100%. Коэффициент рассчитывается сервером и не принимается от клиента.

Акции не занимают клетки и вес инвентаря. Позиции, себестоимость и журнал операций хранятся в `playerJson.stockPortfolio`. Котировка акции едина для всей кампании и не зависит от планеты. На планете хранится только переключатель `stockMarketEnabled`: при значении `true` доступны сразу все акции, при `false` портфель можно просматривать, но покупать и продавать акции нельзя. Диапазон котировки и тикер задаются в карточке снаряжения типа `stock`; вероятность появления к акциям не применяется.

## Защита портфеля и каталога мира 1.0.140

Версия 1.0.140 добавляет два hook-файла:

```text
pocketbase/pb_hooks/grpgi_integrity_v140.pb.js
pocketbase/pb_hooks/grpgi_integrity_v140.js
```

Они устанавливаются рядом со всеми существующими hooks. Каталог `pb_hooks` целиком заменять нельзя. При обновлении с 1.0.139 также замените файл `grpgi_market_v139.js` версией из нового архива: ответ рынка теперь возвращает серверные метки обновления профиля.

Hook проверяет обновления `campaign_players` и не позволяет устаревшему полному профилю удалить или уменьшить `stockPortfolio` без корректного нового элемента биржевого журнала. При запуске он воспроизводит подтверждённые строки `grpgi_market_operations_v139` и добавляет недостающие позиции в портфель, не меняя баланс. Это восстановление не может доказать покупки, совершённые до появления таблицы 1.0.139.

Hook также проверяет `campaign_snapshots`. Если снимок пытается заменить каталог с пользовательскими предметами почти полным встроенным набором без пользовательских ID, сервер оставляет прежний раздел `equipment`. Корректное секционное сохранение World Config и обычные изменения пользовательских предметов разрешены.

Автоматически создаются таблицы:

- `grpgi_portfolio_guard_events_v140` — заблокированные попытки потери портфеля;
- `grpgi_world_section_history_v140` — последние 30 попыток изменения `equipment` для каждой кампании, включая заблокированные;
- `grpgi_market_operations_v139` — создаётся при отсутствии, чтобы порядок загрузки hooks не влиял на запуск.

Подробные команды установки, проверки и отката приведены в `APPLY_PATCH_1.0.140.md`.

## Серверный журнал анкет персонажей

Начиная с версии 1.0.93 регистрация использует отдельные авторизованные маршруты PocketBase. Они создают анкету, возвращают список ожидающих анкет ДМу и проводят одобрение или отклонение. Установите оба файла:

```text
pocketbase/pb_hooks/grpgi_character_applications.pb.js
pocketbase/pb_hooks/grpgi_character_applications.js
```

Скопируйте их в рабочий каталог `pb_hooks` и перезапустите PocketBase. Дополнительная коллекция не нужна: журнал использует существующую `campaign_players`. Клиент показывает успешную отправку только после контрольного чтения созданной анкеты через серверный маршрут. Сервер назначает каждой анкете новый технический `playerId`; удалённая запись с тем же прежним именем и её `deletedAt`/`__deleted` никогда не переиспользуются.

Рынок использует `campaign.marketDate` как текущий игровой день. Изменение этой даты в World Config формирует новые котировки и сохраняет корректное сравнение с предыдущим игровым днём. Если поле не заполнено, временно используется календарная дата UTC.

Если хук отсутствует, синхронизированные клиенты блокируют торговую операцию. Небезопасного клиентского обхода нет.

## Мягкое удаление сообщений

Клиент скрывает удалённое сообщение из интерфейса, но сохраняет серверную запись с исходным `bodyHtml` и меткой `deletedAt`. Чтобы обычный авторизованный клиент не мог физически удалить такую запись, восстановить её или подменить исходный текст, установите серверный хук:

```text
pocketbase/pb_hooks/grpgi_chat_retention.pb.js
```

Скопируйте файл в рабочий каталог `pb_hooks` и перезапустите PocketBase. Хук действует на коллекцию `campaign_messages`. Суперпользователь PocketBase сохраняет право окончательного удаления записи для администрирования и исполнения обоснованного запроса субъекта данных.

Поле `Delete rule` коллекции `campaign_messages` также следует оставить закрытым. Хук является дополнительной защитой от ошибочной или слишком широкой настройки API-правил.

## Передача добычи и выдача денег 1.0.137–1.0.138

Эти функции добавляются к установленным обработчикам игроков и рынка, а не заменяют их. Скопируйте в рабочий каталог `pb_hooks` пять файлов:

```text
pocketbase/pb_hooks/grpgi_loot_v137.pb.js
pocketbase/pb_hooks/grpgi_loot_v137.js
pocketbase/pb_hooks/grpgi_loot_core_v137.js
pocketbase/pb_hooks/grpgi_economy_v138.pb.js
pocketbase/pb_hooks/grpgi_economy_v138.js
```

Перезапустите PocketBase. На старте автоматически создаются две служебные таблицы:

- `grpgi_loot_operations_v137` — подтверждённые передачи предметов при обыске;
- `grpgi_credit_operations_v138` — подтверждённые начисления денег персонажам.

Маршруты:

```text
POST /api/grpgi/loot/transfer
POST /api/grpgi/credits/grant
```

Оба маршрута требуют авторизации, права изменения записи получателя в `campaign_players` и права изменения текущего снимка `campaign_snapshots`. Поэтому обычный игрок не может выдать себе предмет или деньги, даже если знает формат запроса.

Начисление денег принимает только положительное целое число от 1 до 1 000 000 000. Изменение баланса, версии профиля и запись идентификатора операции выполняются внутри одной транзакции. Повтор с тем же `operationId`, персонажем и суммой возвращает `replayed` без второго начисления. Попытка использовать тот же идентификатор с другой суммой отклоняется. Журнал хранится отдельно от JSON профиля и переживает редактирование персонажа и перезапуск PocketBase.

World Config сначала сохраняет намерение начисления локально. Если ответ сервера потерян, повторная кнопка отправляет тот же `operationId`; удалять локальные данные приложения до завершения такого повтора не следует. Старый selfhost-провайдер не поддерживает новый транзакционный маршрут и явно отклоняет безопасную выдачу денег.

Проверка после установки: неавторизованный запрос должен вернуть `401`; авторизованное начисление — `committed`, его точный повтор — `replayed`, а баланс должен измениться один раз.

## Ассеты

Загрузка выполняется в `campaign_assets`. Для отображения изображений через обычные URL настройте View-правило коллекции так, чтобы нужные клиенты могли читать файлы.
