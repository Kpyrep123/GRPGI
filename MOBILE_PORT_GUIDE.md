# Портирование Galactic RPG Interface на Android без потери облачных данных

Этот гайд написан под твой текущий проект, где:
- desktop-приложение на Electron остаётся в корне;
- мобильная версия живёт в подпапке `mobile/`;
- в Supabase уже лежит много данных, и их **нельзя случайно перезаписать или удалить**.

---

## 1. Главный принцип мобильной версии

Мобильный клиент должен быть **player-only** и работать в безопасном режиме:

### Он читает из облака:
- `campaign_snapshots` — мир кампании;
- `campaign_players` — отдельные строки игроков;
- `campaign_messages` — чат;
- `campaign_combat_runtime` — боевой runtime и журнал.

### Он может записывать только:
- **свою** строку игрока в `campaign_players`;
- свои сообщения в `campaign_messages`.

### Он не должен:
- писать в общий `campaign_snapshots`;
- менять DM-данные;
- трогать World Config;
- работать с локальными world-файлами Electron.

Именно это уже заложено в новой мобильной заготовке.

---

## 2. Что уже сделано в проекте

В проект добавлен рабочий player-shell в `mobile/www/`.

Сейчас там уже есть:
- первое окно ввода Supabase-параметров;
- загрузка облака после сохранения конфигурации;
- fallback на локальный кеш телефона;
- вход через выбор персонажа и пароль;
- экран **Навигатор** вместо тяжёлой глобальной карты;
- **Архив**;
- **Торговый терминал** только для текущей планеты;
- **Чат**;
- **Боевые сцены** и живой журнал;
- **Профиль**.

Это не полный финальный продакшен-клиент, но это уже не пустой каркас.

## 4. Что переносим в мобильную версию

Обязательно:
- профиль;
- архив;
- статьи;
- планеты;
- новости и задания;
- чат;
- боевые сцены и журнал;
- торговый терминал текущей планеты.

Не переносим:
- режим ДМа;
- World Config;
- редакторы;
- второе окно ДМа;
- тяжёлые Electron-файловые операции;
- полную тяжёлую глобальную карту.

---

## 5. Почему на телефоне лучше не использовать тяжёлую карту

Ты сам правильно заметил: если тянуть на Android тот же тяжёлый рендер галактической карты, это даст:
- больше нагрузки на GPU и CPU;
- больше глюков в WebView;
- больше шансов на рассинхрон камеры и интерактива.

Поэтому для mobile лучше оставить:
- красивый экран-навигатор;
- карточки систем;
- карточки планет;
- быстрый переход к нужной системе из статей.

То есть игрок на телефоне видит не «редактор карты», а удобный навигационный интерфейс.

---

## 6. Как мобильный клиент должен защищать уже существующие облачные данные

Это самая важная часть.

### Делай так

#### 1. Никогда не пушь общий snapshot из телефона

На мобильной версии **не должно быть вообще никакого кода**, который делает запись в `campaign_snapshots`.

То есть на телефоне не должно быть кнопок и путей вида:
- `PUSH_LOCAL`
- `SAVE_WORLD`
- `saveAll`
- обновление `world_json`
- обновление `state_json` всей кампании

### 2. Разделяй чтение мира и запись игрока

Мобильная версия должна:
- скачать мир через `campaign_snapshots`;
- скачать строки игроков из `campaign_players`;
- наложить строку текущего игрока поверх общего снапшота;
- менять только эту строку игрока.

### 3. Делай optimistic concurrency на строке игрока

При покупке/изменении профиля порядок должен быть таким:
1. прочитать текущую строку игрока;
2. взять её `version`;
3. отправить `PATCH ... where version = expectedVersion`;
4. если версия изменилась — не затирать строку, а сказать клиенту обновиться.

Именно такой безопасный путь заложен в новой заготовке.

## 7. Какие таблицы реально нужны на мобильной версии

По умолчанию мобильный клиент ждёт такие имена:

- `campaign_snapshots`
- `campaign_players`
- `campaign_messages`
- `campaign_combat_runtime`

Они вынесены в форму настройки, так что при необходимости их можно изменить без переписывания кода.

## 8. Первое окно при запуске Android-клиента

Ты просил, чтобы у игроков первым экраном было именно окно ввода Supabase-настроек, как на ПК. Так и надо делать.

### Логика первого запуска

Если локальной конфигурации нет:
- открыть экран подключения;
- сохранить `SUPABASE_URL`, `ANON_KEY`, `CAMPAIGN_ID`, `DEVICE_LABEL`;
- сразу выполнить pull из облака;
- только после успешной проверки открыть выбор персонажа.

### Если конфигурация уже есть

Тогда:
- сразу грузим облако;
- если облако недоступно, но есть кеш — открываем кеш;
- если нет ни облака, ни кеша — возвращаемся на экран настроек.

---

## 9. Почему на телефоне нужен локальный кеш

На Android без кеша пользователь будет зависеть от сети буквально на каждом экране.

Храни локально:
- Supabase config;
- последний snapshot мира;
- последние строки игроков;
- чат;
- боевой runtime;
- активную сессию игрока.

В текущей заготовке это уже заложено через storage-layer с fallback на `localStorage`, а для Capacitor в зависимости добавлен `@capacitor/preferences`.

## 10. Что делает новая мобильная заготовка по экранам

### Навигатор
- показывает текущую систему и текущую планету персонажа;
- показывает видимые системы;
- заменяет тяжёлую карту карточками и быстрым фокусом.

### Архив
- статьи;
- планеты;
- системы;
- новости;
- задания;
- поддержка локальных ссылок `article:ID`;
- кнопка перехода к системе.

### Торговый терминал
- работает только на текущей планете персонажа;
- меняет только строку игрока;
- не трогает общий snapshot.

### Чат
- читает `campaign_messages`;
- умеет отправлять новые строки;
- не трогает мир кампании.

### Бой
- читает сцены из world snapshot;
- читает runtime и журнал из `campaign_combat_runtime`;
- не пытается править DM-runtime.

### Профиль
- показывает stats, кредиты, инвентарь и текущую планету;
- использует overlay из `campaign_players`.

## 11. Как собрать Android-версию

### Шаг 1. Установить зависимости

Из корня проекта:

```bash
npm run mobile:install
```

### Шаг 2. Создать Android-платформу

```bash
npm run mobile:android:init
```

### Шаг 3. Скопировать web-часть в Android-проект

```bash
npm run mobile:sync
```

Если ты менял только `mobile/www/*`, то для быстрого цикла можно использовать и:

```bash
npm run mobile:copy
```

### Шаг 4. Открыть Android Studio

```bash
npm run mobile:open:android
```

### Шаг 5. Запустить

Дальше уже запускаешь из Android Studio:
- либо эмулятор;
- либо подключённый телефон.

## 12. Как безопасно тестировать, чтобы не повредить существующую кампанию

Это критически важно.

### Лучший путь

Сделай **отдельный тестовый `CAMPAIGN_ID`** для мобильного порта, например:

```text
campaign-alpha-mobile-test
```

И сначала проверяй Android-клиент на нём.

### Что именно тестировать

1. Первый запуск без конфигурации.
2. Сохранение параметров Supabase.
3. Загрузку кампании из облака.
4. Вход за игрока.
5. Работу архива.
6. Переходы к системе из статей.
7. Чат.
8. Просмотр боевых сцен.
9. Покупку в терминале.

### Отдельно проверь

После покупки в терминале на телефоне должно измениться только:
- кредиты игрока;
- его инвентарь;
- версия строки в `campaign_players`.

И **не должно измениться**:
- `campaign_snapshots.world_json`;
- `campaign_snapshots.state_json`;
- DM-конфиг.

Мобильная версия переведена на актуальную серверную схему:

- основной backend по умолчанию: PocketBase;

- режим ДМа отсутствует;
- глобальная галактическая карта отсутствует, вместо неё используется лёгкий навигатор;
- доступны архив, торговый терминал, чат, бой, профиль, навыки и репутация;
- добавлен гостевой вход с клиентской фильтрацией видимости;
- добавлена фильтрация персонажей по игровым кампаниям;
- NPC с выключенной перепиской не показываются в мобильном списке чата.
