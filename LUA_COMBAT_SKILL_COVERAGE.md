# Боевые навыки: готовность Lua API v312

Проверен код `origin/main` после PR #169. Этот PR добавляет общие механизмы, а не импортирует новую редакцию каталога навыков. «Можно реализовать» означает, что поведение можно выразить скриптом поверх текущего runtime; это не утверждение, что готовый скрипт уже назначен каждому навыку.

## Ограничения и работа, не выполненная этим PR

1. Трёхстадийный расчёт подключён к движению. Он не объявляется универсальным трёхстадийным пересчётом каждого произвольного поля профиля. Для экипировки остаются отдельные базовые/улучшенные hooks v311, для проверок — событийные бонусы.
2. Нужен отдельный перенос/аудит конкретных скриптов каталога. В частности, существующий Блок щита из `BeforeDamage` не переписывается анализом текста Lua; необходимо явно задать `shieldBlock` и подходящую реакцию `AfterArmor`.
3. Восприятие речи, психологического воздействия, специальные сюжетные запреты и иные неописанные сценой свойства подтверждает ДМ. Для этого есть существующие `RequestConfirm`/выбор целей. Движок не определяет эти свойства по названию сущности или художественному тексту.
4. Сенсоры работают с настроенными параметрами, расстоянием, маскировкой и геометрией сцены. Отдельная симуляция материалов, тепловой сигнатуры, распознавания речи или автономный ИИ не добавлены. Новые датчики задаются данными либо `DefineSensor`.
5. Подготовка хранит декларативное действие и ссылку на источник; Lua-функции/замыкания не сериализуются. Произвольное условие выражается чистым `CanOnPreparedAction` скриптовой заготовки, а не строкой исполняемого кода в сохранении.
6. После отмены с уже подтверждёнными побочными действиями не откатываются эти отдельные расходы. Несостоявшийся выстрел после защитного перемещения не тратит своё Действие/патрон. Для продолжения частично пройденного и остановленного маршрута требуется новая команда.
7. Активные навыки со своим расходом используют `GetCostMode() = 'scripted'`. Это предотвращает второе списание старой автоматической политикой. Нативные базовые действия по-прежнему выполняются штатным путём.
8. Рейды, веб-исполнение боевых скриптов, внебоевые медицинские/ремонтные процедуры и навыки Славы в объём не входят.

## Проверки

Новый `tests/combat-runtime-v312.dom.mjs` загружает реальные renderer-скрипты и Wasmoon worker. Он проверяет стадии движения и смену травмы/массы, компенсацию после деления, запрет движения, физические перебросы и отмену, общую проверку, контрольный взрыв и износ брони до Блока, оружейную очередь и итог Действия, расширенный пул Реакций и сроки чужого/собственного хода, повтор команды после сохранения/загрузки, события до шага, защитный маршрут и расходы атаки, заготовку, связанное перемещение, обнаружение/передачу через сенсор, физическую стену, повтор сложной команды дрона и атомарное выбивание оружия.

Существующие проверки обычной атаки, `StandardAttack`, атаки по возможности, снаряжения, боевого состояния, синхронизации и отключённых рейдов остаются в `npm run test:pr`. Автоматические тесты управляют формами физического ввода; они не заменяют физические кубики в игре и не вводят автоматическую генерацию d20 в приложение.

## Установка

После слияния PR выполнить `git pull` и полностью закрыть/запустить Electron. Новые серверные службы, миграции коллекций, SCP и перезапуск PocketBase не требуются. Общий файл состояния и извлечённая копия математических правил обновлены для согласованности сборки; это не включает рейды. Публикация веб-клиента для исполнения нового боевого API не нужна.
