# Вход персонажей и восстановление пароля v212

Клиент проверяет пароль на сервере PocketBase. Сервер хранит bcrypt-хеш в закрытой auth-коллекции, а профиль, World Config, синхронизация и новые клиентские экспорты не содержат пароль или хеш.

## Установка

Изменение требует согласованного обновления сервера, сайта и настольных клиентов. Вход по локальной копии пароля прекращается. Неподдерживаемый или недоступный сервер возвращает ошибку входа.

1. На сервере создайте защищённую резервную копию pb_data. Она содержит прежние пароли. Остановите старые клиенты на время перехода.
2. Добавьте в действующий pb_hooks ровно два файла из этого PR — grpgi_auth_v212.js и grpgi_auth_v212.pb.js. Остальные установленные hooks сохраняются.
3. Добавьте в действующий pb_migrations файл 1793923200_player_auth_v212.js.
4. Задайте переменную окружения GRPGI_WEB_URL с точной HTTPS-ссылкой на веб-приложение, например https://app.grpg-sync.ru/app/. Она используется для ссылок восстановления. Не добавляйте фрагмент #. После изменения окружения перезапустите сервис.
5. При остановленном сервисе выполните pocketbase migrate up, затем запустите сервис. Нужны действующие коллекции campaign_players и campaign_snapshots со стандартными именами. Миграция выполняется транзакционно. Если структура отличается, сначала адаптируйте миграцию на тестовой копии базы.
6. Обновите настольные исходники целиком, включая main.js, preload.js и новые renderer-модули, и перезапустите клиент. Выполните Deploy Web. Старые клиенты после миграции несовместимы с новым входом и защищённой записью.
7. Проверьте вход игрока и ДМа, регистрацию с одобрением, сохранение World Config, покупку, чат и цикл восстановления. Для проверки истёкшей сессии повторите запись после смены пароля.

Модуль и миграция проверены на PocketBase 0.36.3. Рабочий сервер этой задачей не изменялся. Дополнительные установленные серверные hooks, отсутствующие в репозитории, следует проверить на тестовой копии вместе с новым middleware. Прокси должен пропускать X-GRPGI-Session.

## Миграция

- Сначала используются актуальные campaign_players, затем недостающие персонажи из снапшотов. Пароль из старого снапшота не заменяет пароль актуальной строки.
- Старые короткие пароли сохраняют возможность входа. При регистрации и сбросе новый пароль должен иметь не меньше 8 символов и не больше 72 байт UTF-8.
- Персонажу без сохранённого пароля создаётся случайный недоступный ему секрет. Для обычного игрока используется восстановление через ДМа. Доступ к учётной записи ДМа в такой ситуации восстанавливает администратор сервера.
- Пароли удаляются из текущих профилей и снапшотов. Обновлённый клиент очищает загружаемые данные, новые экспорты, сохраняемое состояние и новые резервные копии кампании.
- Ранее созданные резервные копии, выгрузки, старые установки и сторонние копии не изменяются. Отозвать знание ранее раскрытого пароля невозможно.
- Миграция не имеет автоматического обратного преобразования хеша в пароль. Для отката нужна защищённая резервная копия и прежние версии всех клиентов.

## Полномочия ДМа

Закрытая коллекция grpgi_credentials_v212 связывает учётную запись с серверной кампанией и ID персонажа. Признак ДМа переносится при миграции. Подмена поля role в обычном профиле не даёт прав подтверждения восстановления.

Создание нового ДМа и изменение этого полномочия выполняет администратор PocketBase через закрытую коллекцию. Созданный через World Config новый обычный персонаж получает доступ через восстановление. Пароль в редакторе World Config больше не задаётся.

Серверная кампания подключения (campaignId в конфигурации синхронизации) и игровая кампания в селекторе — разные значения. Учётные записи и запросы восстановления привязаны к первой.

ДМ получает возможность передать доступ игроку через одноразовую ссылку. Новый пароль игрок задаёт самостоятельно. ДМ, располагающий ссылкой до её использования, также может воспользоваться ею — подтверждение запроса является доверенной административной операцией.

## Восстановление

Игрок выбирает персонажа на входе и нажимает «Забыли пароль?». Ответ одинаков для существующего и отсутствующего персонажа. Сам запрос не меняет действующий пароль.

ДМ открывает в профиле «Запросы восстановления пароля», проверяет личность игрока через известный контакт и выдаёт ссылку либо отклоняет запрос. Ссылка показывается только в ответ на выдачу. Повторная выдача отменяет предыдущую. На сервере сохраняется только хеш токена.

Ссылка открывает то же приложение с фрагментом #recover=... . Фрагмент удаляется из адресной строки после открытия формы. В настольном клиенте ссылку можно вставить через «Ввести ссылку».

Ссылка действует 30 минут и используется один раз. Смена пароля и погашение ссылки выполняются в одной транзакции. Все прежние сессии персонажа и остальные ссылки восстановления становятся недействительными. После сброса игрок входит обычным способом.

## Сессии и совместимость маршрутов

Сервер выдаёт сессию до 30 дней. Сохранённый вход проверяется сервером. Заголовок X-GRPGI-Session прикладывается к запросам обновлённых клиентов.

Middleware проверяет сессию при изменениях через старые /api/grpgi/ и стандартные REST-маршруты игровых коллекций. Обычный игрок изменяет свою строку, свои сообщения и выполняет свои рыночные операции. World Config, боевой runtime, одобрение анкет и выдача денег требуют ДМа.

Публичная регистрация остаётся доступной, но не может перезаписать существующую учётную запись. Секундный биржевой worker сохраняет отдельную проверку своего серверного токена. Публичное чтение существующих игровых справочников не перерабатывается этим PR.

Добавлены постоянные ограничения частоты входа, регистрации, запросов восстановления и попыток использования ссылки. Учётные записи и токены восстановления не доступны через обычные CRUD-правила PocketBase.
