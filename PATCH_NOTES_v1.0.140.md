# GRPGI 1.0.140

Накопительный патч для исходной версии 1.0.136. Он включает изменения 1.0.137–1.0.139 и исправляет два независимых критических сбоя: исчезновение купленных акций у игрока и возврат каталога снаряжения World Config к встроенному набору.

## Что было установлено

Исчезновение акций не связано с инвентарём персонажа. Акции хранятся отдельно, в `playerJson.stockPortfolio`, поэтому снаряжение игрока при таком сбое остаётся на месте.

В коде рынка нет задания, которое в полночь удаляет портфели. Смена календарной даты может изменить отображаемую рыночную ротацию, если в кампании не задан `marketDate`, но не записывает пустой портфель. Реальная потеря могла происходить двумя путями:

- старое полное сохранение профиля не сохраняло неизвестные ему поля, включая `stockPortfolio`;
- конфликтующее realtime-событие с той же версией записи принималось поверх уже полученного результата покупки.

Сброс World Config имел другой источник:

- при отсутствии или повреждении локального `equipment.json` приложение сначала подставляло встроенный файл, из-за чего исправная резервная копия уже не выбиралась;
- сохранение одного раздела могло отправить полный снимок мира и заменить серверный каталог устаревшей локальной копией;
- локальные JSON-файлы записывались непосредственно, поэтому прерванная запись могла оставить неполный файл.

## Защита портфеля акций

- Локальная нормализация профиля теперь сохраняет все поля записи, в том числе `stockPortfolio`, а не собирает профиль из ограниченного списка.
- ПК- и веб-клиент отклоняют конфликтующее realtime-событие той же версии, если оно не новее уже принятой записи.
- Ответ пакетной торговой операции содержит серверные метки времени и автора изменения, поэтому клиент может корректно сравнить его с последующими событиями.
- Новый серверный hook проверяет изменение `stockPortfolio` в `campaign_players`. Удаление или уменьшение позиции без подтверждённой записи журнала блокируется, а остальные поля профиля продолжают сохраняться.
- При первом запуске hook воспроизводит покупки и продажи из `grpgi_market_operations_v139` и восстанавливает недостающие позиции без повторного списания или начисления денег.
- Заблокированные попытки записываются в `grpgi_portfolio_guard_events_v140` — это позволяет установить время и источник старого сохранения.

Автовосстановление возможно для операций, которые уже попали в журнал версии 1.0.139. Покупки, совершённые до установки 1.0.139 и отсутствующие в этом журнале, автоматически доказать и восстановить нельзя; их нужно сверять с резервной копией или выдавать вручную.

## Защита каталога снаряжения World Config

- При запуске порядок восстановления теперь такой: рабочий JSON → последняя локальная резервная копия → встроенный шаблон.
- Рабочие файлы мира и локальное состояние записываются атомарно через временный файл и переименование.
- Перед каждой записью раздела создаётся проверенная резервная копия; хранится последняя копия и до 12 исторических копий каждого раздела.
- Облачное сохранение стало секционным: редактирование снаряжения меняет только `equipment`, редактирование NPC — только `npcs` и так далее. Обычные сохранения профиля вообще не имеют права менять общий мир.
- Клиент останавливает отправку, если новый каталог неожиданно совпал со встроенным набором и удаляет серверные предметы.
- Новый серверный hook повторяет эту проверку независимо от клиента. Подозрительный снимок сохраняется в журнал, а сервер оставляет прежний `equipment`.
- История попыток изменения каталога хранится в `grpgi_world_section_history_v140` (последние 30 записей для кампании и раздела).

## Серверные файлы 1.0.140

Добавляются:

```text
pocketbase/pb_hooks/grpgi_integrity_v140.js
pocketbase/pb_hooks/grpgi_integrity_v140.pb.js
```

Также обновляется существующий файл:

```text
pocketbase/pb_hooks/grpgi_market_v139.js
```

Каталог `pb_hooks` целиком не заменяется. Старые hooks синхронизации, рынка, анкет, чата, добычи и денег должны остаться на сервере.

## Проверки

- Воспроизведено состояние «деньги списаны, портфель пуст», затем проверено автоматическое восстановление после запуска PocketBase с hook 1.0.140.
- Проверено блокирование старого полного профиля, который пытается удалить акции.
- Проверена разрешённая продажа акций через маршрут 1.0.139.
- Проверено блокирование встроенного каталога поверх каталога с пользовательским предметом и разрешение обычного редактирования.
- Проверено восстановление отсутствующего/повреждённого `equipment.json` из резервной копии, атомарная запись и секционная синхронизация.
- Повторно пройдены тесты быстрой синхронизации инвентаря, навыков, рынка, добычи, выдачи денег, Lua API, World Config и браузерного интерфейса.

Установка и команды проверки описаны в `APPLY_PATCH_1.0.140.md`.
